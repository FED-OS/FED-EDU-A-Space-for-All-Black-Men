# Fork (GitHub)

**Category:** tools · **Added by:** fedpromptly · **Level:** beginner

## 🗣️ Plain Talk Translation

A **fork** is copying somebody's whole workshop — blueprints, tools, half-finished projects, everything — to make YOUR own version. The original workshop stays untouched. You can change anything in your copy, no permission needed, because it's yours now.

The magic part: your copy remembers where it came from. When the original workshop upgrades, you can pull those upgrades over. And when you build something the original wants, you can offer it back.

## 🎵 Life Example

The mixtape. A producer takes a track, chops it, flips it, lays new drums, makes it HIS — and the original still stands, untouched, on its own shelf. Nobody asks the original's permission to remix; the remix culture IS the permission.

That's forking. Every hip-hop producer who ever flipped a sample was forking before GitHub existed. Hip-hop built the culture of remix-as-respect; open source built the tooling. Same spirit, different century.

## 💻 What It Looks Like

One button. On any GitHub repo page: **Fork** (top right). Ten seconds later you own `github.com/YOUR-NAME/their-project` — a full copy, connected to the original.

The flow you'll actually use (the block's flow):

```
Fork → build in your copy → Commit your work →
Open a Pull Request → "main block, I made something — check it" → Merge
```

Four moves, and every one is covered step-by-step in [wiki/First-Steps](../wiki/First-Steps/Fork-Your-First-Repo.md).

## ⚠️ The One Trap (Sync Fork)

Your fork is a **snapshot**, not a mirror. When the original updates, your copy does NOT follow automatically. If you build on old code for weeks, merging back gets painful.

The habit: before starting new work in your fork, hit **"Sync fork" → Update branch** on your fork's page. Ten seconds. Saves hours. (Full walkthrough in the wiki.)

## 💰 Where It Pays

Every open-source contribution — the ones that build the résumé that gets you hired — starts with a fork. "I contribute to open source" on a job application means "I fork, improve, and PR." Interviewers know the pipeline. Your GitHub contribution graph (the green squares) is literally a fork-driven résumé that updates itself while you sleep.
