# 🤝 FED-EDU CONTRIBUTING — How Any Brother Can Build With Us

> You don't need permission to contribute. You need a GitHub account, an idea, and respect for the ground rules. Here's how every kind of contribution works.

## First, The Vibe Check

Read `CODE_OF_CONDUCT.md`. Short version: no gatekeeping, no judgment, celebrate attempts, explain everything in plain terms. If you got questions about how we talk to each other here, that file is the answer.

## The Five Ways To Contribute

### 1. Fix & improve (code)
Everything runs on GitHub, so the standard flow works:
1. **Fork** the repo — copying the blueprint to your own account
2. **Clone** it down to your machine (or edit right in the browser on a phone — totally valid here)
3. **Make your change** — start small. Fix a typo, improve a guide, tighten a script
4. **Commit & push** — save your work with a message that says what you did
5. **Open a Pull Request** — use the template, keep the summary in plain terms

First PR? Say so in the description. The community daps first-timers hard — that's Rule 3.

### 2. Teach (wiki & guides)
Know something others don't? Write it down the way you'd explain it to your little cousin. Add a wiki page in `wiki/`, a term in `urban-dictionary/terms/`, or a course improvement. Plain terms, short sections, working examples.

### 3. Build (blueprints & projects)
Fork a sandbox blueprint, customize it, ship it. Then post your live link in the Ship Yard discussion and the showcase vault (`community-boards/showcase-vault/`). Your build might be the thing that makes the next brother believe it's possible.

### 4. Represent (community)
Welcome new brothers in the Spawn Zone. Answer Help Desk issues — especially `[NEED-PLUG]` and `[STUCK-IN-THE-LAB]` tags. Share the movement on your platforms. Being present is contribution.

### 5. Fund (support-the-block)
Ko-fi contributions buy refurbished desktops and data plans. Money is fuel, not membership — but it keeps brothers online. See the button in `README.md`.

## What Gets Merged Fast

- Typo and broken-link fixes — just ship them
- Plain-terms translations of confusing docs
- New urban-dictionary entries
- Wiki pages that follow the existing format
- Bug fixes with a clear before/after
- Blueprint improvements that keep files lightweight (they must load on EasyTether connections — that's a hard requirement)

## What Needs A Vote First

See `GOVERNANCE.md` for the levels, but broadly: new modules, manifesto changes, pricing standards, anything spending community funds, and partnerships. Propose in the discussions with the `[PROPOSAL]` tag.

## Style Rules (The Only Ones That Matter)

1. **Plain terms.** Docs read like a big brother talking, not a textbook. Technical accuracy wrapped in real language.
2. **Lightweight or it doesn't ship.** Frontend files stay lean — no heavy frameworks that break tethered connections. If it doesn't load on a scrap PC through a phone, it doesn't merge.
3. **No unnecessary jargon.** New term introduced? Translate it inline and add it to the urban dictionary.
4. **Respect file sizes.** Images compressed, media lazy-loaded, scripts small. Data costs money for half the brothers here.
5. **Comments in code are welcome.** Especially ones that explain *why*, in plain terms, for the next brother.

## Becoming A Maintainer

There's no application form. Maintainers are brothers who consistently ship, help others, and keep their wing clean. When a module needs hands, existing maintainers tap the most consistent contributors. That's the whole pipeline: show up, build, get trusted with a room.

## Getting Help While Contributing

Stuck? That's what the Help Desk is for — open an issue with the `[NEED-PLUG]` or `[STUCK-IN-THE-LAB]` tag and brothers will pull up. No question too basic. We mean that literally — "how do I save a file" gets answered with the same energy as "why is my API call failing."

## The Receipts

Contributors get credited in `AUTHORS.md`, in release notes (`CHANGELOG.md`), and in git history — the permanent record. Your GitHub profile IS your resume here, and this org's history becomes part of your story.

Ship something every week, even small. That's the culture.
